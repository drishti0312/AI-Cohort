### 11.1 Practitioner Review

| **AI tool**       | **Review comment**                                                                                                                                                        | **Accept or reject**       | **Reason**                                                                                                                                                                                       | **Change**                                                                                                 | **Evidence**                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| ChatGPT + Copilot | The agent uses a limited set of behavioural signals: amount, location, merchant, frequency, and velocity. Real-world fraud systems would use more contextual information. | **Accept as a limitation** | Both reviews pointed out that the current evidence is simplified. I agree, but I want to keep the first version small and understandable.                                                        | Added this as a limitation and future improvement.                                                         | The current agent uses five behavioural signals.                                                      |
| ChatGPT           | Asking customers to verify legitimate transactions can create unnecessary customer friction.                                                                              | **Accept**                 | Customer experience is important. Too many verification requests could frustrate legitimate customers even if the agent is detecting fraud correctly.                                            | Customer interaction/review rate is included as an evaluation metric.                                      | Policy A had an interaction rate of 8.58% and Policy B had an interaction rate of 8.54%.              |
| ChatGPT           | The Question action is useful because it allows the agent to collect additional information before making a final decision.                                               | **Accept**                 | This supports the main idea of making decisions under uncertainty. The agent does not always have to immediately approve or decline.                                                             | No major change. Question remains one of the four actions.                                                 | FREQ_C0514 was initially given Question and was later Declined after additional information.          |
| ChatGPT           | The Examine action can create additional work for human investigators if too many transactions are escalated.                                                             | **Accept**                 | Human review has limited capacity, so escalation also has a cost.                                                                                                                                | Examine cases are reported separately when comparing the policies.                                         | Policy A examined 10 transactions, while Policy B examined 52.                                        |
| ChatGPT + Copilot | The probability model assumes the evidence signals are independent, although some signals may be related.                                                                 | **Accept as a limitation** | Both reviews raised this issue. The assumption keeps the model simple, but it may not represent real transaction behaviour perfectly.                                                            | Kept the current model and recorded the independence assumption as a limitation and future improvement.    | `calculate_fraud_belief()` multiplies the likelihoods of the five evidence signals.                   |
| ChatGPT + Copilot | The Boolean representation of evidence loses information about how unusual a transaction actually is.                                                                     | **Accept**                 | Both reviews identified this limitation. For example, a transaction that is 4.1× the normal amount and one that is 10× the normal amount can both become `True`.                                 | Keep the current version for the experiment. Consider continuous or more detailed features in future work. | The current evidence functions return mainly `True` or `False`.                                       |
| ChatGPT           | An unusual location should not automatically be treated as fraud because legitimate customers can make transactions from new locations.                                   | **Accept**                 | A customer could be travelling or using the card somewhere new. Location should therefore be considered together with other evidence.                                                            | No standalone decision is made using location.                                                             | The agent combines location with amount, merchant, frequency, and velocity evidence.                  |
| ChatGPT           | The customer-response simulator uses the hidden fraud label to determine the simulated customer's response.                                                               | **Accept**                 | This is an important limitation because a real customer-response process would not have access to the hidden fraud label.                                                                        | Documented this limitation. Future versions should use noisy/probabilistic or real human feedback.         | `simulate_customer_response()` currently checks the transaction's hidden `fraud` value.               |
| ChatGPT           | The current agent should not be considered production-ready.                                                                                                              | **Accept**                 | The dataset is synthetic and several parts of the agent are simplified, especially the probability model and customer-response simulator.                                                        | Clearly described the project as an experimental prototype.                                                | These limitations are documented in the README.                                                       |
| ChatGPT           | More stakeholders should be considered, including customers, merchants, fraud analysts, and payment-system operators.                                                     | **Accept**                 | The agent's decisions affect more people than just the model owner. Customers can experience friction, while analysts may receive additional investigation work.                                 | Added these stakeholders to the limitations and future considerations.                                     | The four actions have different effects on customers and investigators.                               |
| Copilot           | The current binary hidden state of Fraud vs. Legitimate is a simplification of real-world fraud situations.                                                               | **Reject for now**         | Real-world fraud can be more complicated, but the current project is intentionally scoped to a binary hidden state. Adding more states would increase the scope without helping this experiment. | No change. Keep Fraud vs. Legitimate.                                                                      | The current problem statement and probability model use a binary hidden state.                        |
| Copilot           | The 5% fraud prior is manually selected and is different from the dataset fraud rate of about 16.7%.                                                                      | **Accept as a limitation** | The 5% prior was an intentional design choice. I do not want to change it after completing the experiment, but testing different priors would be useful later.                                   | Documented the 5% prior and added prior sensitivity analysis as future work.                               | `calculate_fraud_belief()` uses `prior_fraud = 0.05`, while the dataset has about 16.7% fraud.        |
| Copilot           | Missing evidence could be handled using more advanced methods such as marginalization or imputation.                                                                      | **Reject for now**         | The current implementation treats missing evidence as neutral by assigning both fraud and legitimate likelihoods a value of 1. This is sufficient for the current prototype.                     | No change. More advanced missing-data handling can be considered later.                                    | Missing location or merchant is currently handled without favouring either state.                     |
| Copilot           | The action costs are manually chosen and are not based on real business costs.                                                                                            | **Accept as a limitation** | The costs are useful for testing the decision-making idea, but they should not be treated as real financial estimates.                                                                           | Keep the current costs and describe them as assumed costs.                                                 | `calculate_action_costs()` uses fixed costs for the four actions.                                     |
| Copilot           | Policy B thresholds of 0.20, 0.50, and 0.80 are manually selected and could be tuned using validation data.                                                               | **Accept as future work**  | The thresholds were created to test a second policy and have not been shown to be optimal.                                                                                                       | Keep the current thresholds for the experiment and consider threshold tuning later.                        | `choose_action_threshold()` uses 0.20, 0.50, and 0.80.                                                |
| Copilot           | The fraud beliefs have not been tested for probability calibration.                                                                                                       | **Accept**                 | A probability such as 0.60 should ideally correspond to similar transactions being fraudulent around 60% of the time. This has not been tested yet.                                              | Add probability calibration as a future evaluation.                                                        | No calibration curve or Brier score was calculated in the current experiment.                         |
| Copilot           | A hybrid policy could combine cost-sensitive decisions with interpretable thresholds.                                                                                     | **Accept as future work**  | This is an interesting direction, but the current experiment already compares two different policies.                                                                                            | Consider a hybrid policy in a future version.                                                              | Policy A uses cost minimization and Policy B uses fixed thresholds.                                   |
| Copilot           | The current probability model can be described as a simplified Naive Bayes-style approach.                                                                                | **Accept**                 | This description makes the current probability approach and its independence assumption clearer.                                                                                                 | Use this description in the paper/README.                                                                  | `calculate_fraud_belief()` combines a prior with likelihoods for the different evidence signals.      |
| ChatGPT + Copilot | The current experiment should not be changed after testing just because the reviews identified possible improvements.                                                     | **Accept**                 | The reviews are useful for identifying limitations and future improvements, but changing the tested agent now would make the reported experiment inconsistent.                                   | No changes to the tested version. Record improvements as future work.                                      | Policy A, Policy B, and the failure analysis were already completed using the current implementation. |
